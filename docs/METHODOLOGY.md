# Methodology: reproducing the regional satellite clarity model

This page states what a reader can re-run from this repository, what they cannot, and the exact settings of every step. Every parameter below was read from the scripts in `scripts/`, and the manuscript's Methods section states the same values. The numbers a re-run should reproduce are in [`results/README.md`](../results/README.md).

## What can and cannot be reproduced today

| Item | Status |
|---|---|
| Landsat extraction, masking, features, model settings, validation logic | Fully specified in the scripts and in the Methods |
| Training data | A new run of script 01 cannot reproduce the paper's data exactly: it queries the Water Quality Portal live, with no end date and no recorded retrieval date, so it returns whatever the portal holds now. The latest reading in the paper's training data is dated 1 October 2025. The authors' saved matching output (`matched_landsat.csv`) and cleaned readings (`insitu_secchi_clean.csv`) rebuild the paper's training table exactly |
| Training table, trained model, cross-validation output | Not in this repository (`data/processed/` is git-ignored); held by the authors. Verified 21 October 2026: scripts 05 and 10 on the saved files give 19,510 rows before and 19,403 rows at 1,383 sites after the Squam exclusion; cross-validation r = 0.507, R² = 0.256, MAE 1.583 m, RMSE 2.047 m, matching the file saved by the original run to six decimals |
| Squam-area exclusion | Done by station name; checked by name, station code and position (`09_training_table_cv_and_squam_check.py`): no other Squam or Little Squam record is in the training data |
| Validation inputs (13 site coordinates, the field readings file) | Not in this repository (`data/raw/` is git-ignored); held by the authors. Running script 11 with `--skip-extract`, then script 12, on the saved 13-site extraction reproduces the committed 445 matched pairs (predictions identical to 1e-15 m) |

## Requirements
Python 3, `requests`, `pandas`, `numpy`, `scipy`, `scikit-learn` (record the version you use), `joblib`, `earthengine-api`. A Google Earth Engine account and your own project ID: set `EE_PROJECT` in scripts 04 and 11 (the repository value is the authors' project) and run `earthengine authenticate` once.

## Steps (run from the repository root)
| # | Command | What it does and the exact settings | Writes |
|---|---|---|---|
| 1 | `python scripts/01_pull_epa_secchi.py` | Water Quality Portal Result search, states NH (US:33), VT (US:50), ME (US:23); characteristics "Depth, Secchi disk depth" and "Water transparency, Secchi disc"; site types "Lake, Reservoir, Impoundment"; sample media Water. **No date filter.** Note the date you run it | `data/raw/epa_secchi_raw.csv` |
| 2 | `python scripts/02_pull_epa_stations.py` | Station coordinates and names | `data/raw/epa_stations_raw.csv` |
| 3 | `python scripts/03_clean_insitu_data.py` | Join to stations; keep unit "m"; keep 0 < depth ≤ 20 m; drop rows missing value, coordinates or date; drop exact duplicates (same site, date, value). Repeated readings at a site are kept | `data/processed/insitu_secchi_clean.csv` |
| 4 | `python scripts/04_match_landsat.py` | Readings from 1984-01-01 (`--start-date`). For each reading, Earth Engine joins every Landsat Collection 2 Tier 1 Level-2 scene (`LANDSAT/LT04`, `LT05`, `LE07`, `LC08`, `LC09` `/C02/T1_L2`) that covers the point within ±3 days of the reading date (time difference measured in milliseconds from the reading date at 00:00 UTC to the scene start time), drops scenes acquired December–March, and keeps the nearest in time. Surface reflectance = DN × 0.0000275 − 0.2. Pixels masked if QA_PIXEL bit 1 (dilated cloud), 3 (cloud), 4 (cloud shadow) or 5 (snow) is set. Bands harmonised to blue, green, red, NIR, SWIR1, SWIR2 (TM/ETM+ SR_B1–B5, B7; OLI SR_B2–B7). 45 m buffer around the point, 30 m scale; median, min, standard deviation and count per band. If the nearest scene has no valid pixel, the reading is dropped later, not matched to another scene. Chunks of 150, resumable | `data/processed/matched_landsat.csv` |
| 5 | `python scripts/05_build_features.py` | Keep readings from 1984-01-01 with valid medians in all six bands. Features (35): scene cloud cover, pixel count (blue count), median/min/standard deviation of each of six bands (18), and the 15 pairwise ratios of band medians (ratio = band1 / (band2 + 1e-6)). No minimum pixel count in training | `data/processed/model_training_table.csv` |
| 6 | `python scripts/06_train_model.py` | Random forest regression: 500 trees, unlimited depth, minimum leaf size 3, `random_state=42`, untransformed Secchi depth. 10-fold `GroupKFold` grouped by `site_id` (monitoring site, not lake). This version trains on all rows including Squam-area sites, so it is **not** the model used in the paper | model, CV JSON |
| 7 | `python scripts/10_train_model_heldout.py` | The model used in the paper: same settings, after removing rows whose site name matches the regular expression `(?i)^squam lake|little squam` | `rf_model_heldout.joblib`, CV JSON |
| 8 | `python scripts/11_predict_multipoint.py` | For each of the 13 Squam-area sites (file `data/raw/squam_multipoint_coordinates.csv`, columns `SLA_Site_Name`, `Matched_NHDES_Station`, `Latitude`, `Longitude`), every non-winter scene from 1984 to 2026, same masking and 45 m window; scenes with fewer than 5 valid pixels dropped; prediction from the model in step 7 | `output/squam_predicted_secchi_multipoint.csv` |
| 9 | `python scripts/12_validate_multipoint.py` | Field readings (file `data/raw/squam_real_secchi_validation_bysite.csv`, columns `Lake`, `Site`, `Date`, `Secchi`) averaged by site and date, paired with the prediction at the same site within ±3 days | `output/matched_tolerance_3day_multipoint.csv`, report |
| 10 | `python scripts/14_make_manuscript_figures.py` | Figures 1 and 2 | `output/manuscript_figure_*.png` |

Scripts 07, 08, 09 and 13 are earlier validation rounds (lake-wide points, original model) and are not behind the paper's final numbers. The comparison of the national and regional products on the same 29 years and 292 site-dates uses the Squam Lakes Association July means, which are not published here; its output tables are in `results/` (`comparable_sample_metrics.csv`, `supp_datelevel_national_vs_regional.csv`). The metric and check scripts are in `analysis/`.

Values in the paper to compare after a re-run: cross-validation r = 0.51, RMSE 2.05 m; 19,403 training readings at 1,383 locations after removing 107 readings at 16 Squam-area sites; 817 eligible field readings, of which 445 matched a prediction (68 dates, 33 years); pooled r = 0.264, RMSE = 2.29 m, bias = −1.70 m. If the Water Quality Portal has changed since the original pull, the training counts and metrics will differ slightly; report the new values and the retrieval date.

## Re-running without Earth Engine
With `insitu_secchi_clean.csv` and `matched_landsat.csv` in `data/processed/`: `python scripts/05_build_features.py`, then `python scripts/10_train_model_heldout.py`. With `squam_multipoint_landsat_extracted.csv` in `data/processed/` and the two files in `data/raw/`: `python scripts/11_predict_multipoint.py --skip-extract` (the script imports `earthengine-api` at the top, so install it or comment out `import ee`), then `python scripts/12_validate_multipoint.py`. Earth Engine is needed only to re-extract Landsat values. On 21 October 2026 this route reproduced the paper's training counts and all 445 matched validation pairs (see `results/validation_rerun_vs_committed.txt`).

## Limitations of what is archived here
1. **Live, undated training pull.** Script 01 has no end date and the retrieval date was not recorded. The latest reading in the paper's training data is dated 1 October 2025. For a new pull, save the raw file with its retrieval date and a SHA-256 checksum.
2. **Intermediate files are not in the repository.** The training table, trained model, cross-validation file, matching output and 13-site extraction are held by the authors. Archive them (a GitHub release or a Zenodo deposit with a DOI) if a reader needs them.
3. **Squam-area exclusion is by station name.** The pattern would miss a Squam-area station stored under another name (it misses SQUAM1WEST, SQU14AL and SQU20BL in the NHDES files). None of those or any other Squam-area station is in the Water Quality Portal training data (checked by name, station code and position: `results/training_squam_check.txt`), so the held-out model had not seen either lake. An exclusion by station list or bounding box would be more robust for a new pull.
4. **Validation inputs are not published.** The 13-site coordinate file and the field-reading file are not in this repository. The Squam Lakes Association and NHDES readings are available from those organisations; the NHDES extracts are in `data/nhdes/`.
